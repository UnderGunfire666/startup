# 事件系统设计计划

## 目标

事件系统不是独立剧情系统，而是现有空间、行动、经营和多店系统上的动态扰动与信息获取层。

优先覆盖三类事件：

1. 调查随机发现（Research Discovery）
2. 玩家所在区块随机事件（World / Block Event）
3. 店铺营业事件（Store Operating Event）

## 核心设计决策

### 1. 调查系统采用“确定性进度 + 随机事件”的混合模型

保留现有 `block_understanding` / 调查进度机制，不改成纯随机获取信息。

原因：

- 纯随机会导致玩家重复调查却长期得不到关键经营信息。
- 门面发现等关键流程节点不能依赖运气，否则会阻断“调研 → 发现门面 → 尽调 → 选址 → 开店”的核心循环。
- 进度系统可以提供明确、可预期的最低收益；随机事件负责增加变化、惊喜和额外信息。

### 2. 固定进度事件负责关键里程碑

调查达到指定进度阈值时，触发确定性结果。例如：

- 达到早期阈值：发现该区块存在的门面。
- 达到中期阈值：揭示更可靠的客群、需求、竞争、租金或时段信息。
- 达到高进度阈值：提供接近完整的区块经营画像。

关键里程碑事件应保证一次触发、不可因为随机失败而错过。

现有门面发现逻辑应继续作为确定性进度奖励，而不是改成纯随机事件。

### 3. 随机调查事件与进度解耦

随机事件不承担核心流程推进职责。

它们用于：

- 额外增加 `block_understanding`。
- 提前揭示部分商业信息。
- 提前发现某个门面，但不能成为唯一发现方式。
- 获得竞争、客群、租金、客流、时段等局部情报。
- 获得少量玩家资源变化或临时效果。

随机事件可以受区块类型、tags、时间、玩家当前位置、当前行动和已有知识影响，但不要求玩家必须达到某个调查进度才能触发。

### 4. 事件作用域

事件必须显式区分作用域，避免重新引入单店假设：

- PLAYER：玩家资源、精力、压力、知识。
- BLOCK：单个区块的临时状态或情报。
- CITY_REGION：城市区域层效果。
- STOREFRONT：门面相关事件。
- STORE：单家企划或已开业店铺事件，必须显式 `store_id`。

### 5. 三种事件交互级别

- NOTICE：纯通知，不暂停时间。
- DECISION：需要玩家选择，可进入待处理事件。
- INTERRUPT：少量重大事件，允许暂停时间。

多店经营后禁止所有事件都强制弹窗暂停。

## 推荐实现顺序

### Phase 1：调查随机发现 MVP

保留 `region_research`、`block_understanding` 与门面发现阈值。

新增一个独立事件解析层，在调查过程中按一定时间间隔尝试触发随机发现。

流程：

`region_research → 调查进度正常增长 → 检查固定阈值事件 → 尝试随机调查事件 → 应用知识/发现结果`

### Phase 2：玩家所在区块随机事件

基于：

- `PlayerState.current_block_id`
- 当前时间
- 区块类型和 tags
- 当前行动
- cooldown

进行筛选和抽取。

### Phase 3：店铺营业事件

在每家营业 Store 的小时结算附近触发，目标必须显式 `store_id`，不得依赖 `GameManager.store_state` 代表全部店铺。

### Phase 4：Temporary Modifier

支持事件对客流、转化、成本、服务效率、采购价格等产生持续数小时或数天的临时影响。

## 架构边界

不建议让一个 EventManager 直接修改所有系统状态。

推荐拆分：

- EventDefinition：静态事件定义。
- EventResolver：条件、权重、cooldown、抽取。
- ActiveEvent：运行时事件实例。
- EventEffectResolver：把结果提交给正确领域。
- UI：展示事件和玩家选择。

Player effect 应作用于 PlayerState 或对应业务 API；Store effect 必须显式 `store_id`；时间仍归 TimeManager；行动上下文仍归 ScheduleManager。

## 调查事件的玩法原则

- 玩家每次调查都应有稳定进展，不能因为 RNG 完全白费。
- 关键开店链路信息必须可通过确定性进度获得。
- 随机事件负责惊喜、提前获得信息、额外收益和世界感。
- 随机事件不能成为发现门面、完成尽调、选址等核心流程的唯一入口。
- 后续可根据 `block_understanding` 让同一事件显示不同精度的信息，但事件是否发生本身不必绑定进度。
